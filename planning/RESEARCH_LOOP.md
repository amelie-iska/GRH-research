# GRH research loop

Created on2026-11-02 at the user's request. App automation identifier: `grh-research-loop`. Status verified ACTIVE. Cadence: hourly. Kind: heartbeat attached to the existing research chat. The app-managed saved prompt is the scheduler's source of truth; this file documents the intended workflow.

## Each run

1. Read current instructions, Git status, README, progress record, claim ledger, open obligations and latest research notes. Resume the recorded frontier rather than repeating completed reviews.
2. Choose one concrete load-bearing unresolved claim. Prioritize the arithmetic self-adjoint determinant/zero-location bridge for the convergent approximants, or a precise mean-square/contour estimate identified in the exponent report.
3. Attempt a proof, replacement construction or decisive counterexample. Record exact assumptions, derivations and failed steps. Rotate after documenting a blocked approach; do not repeatedly restate the plan.
4. Add actual Lean/mathlib verification where applicable, inspect full theorem types and axiom dependencies, and seek independent critical review of major advances.
5. Run focused checks. Update both TeX/PDF editions when substantive article content changes. Preserve the source clones, pinned dependencies, caches and unrelated work.
6. Leave a durable handoff: attempted claim, evidence, proof status, checks, result and next concrete step. Push substantive verified milestones to the private repository using existing authenticated GitHub CLI access and credential/integrity checks.

## Completion and communication

The loop continues while the objective is unresolved unless the user pauses or cancels it. It must not call an equivalent reformulation, finite computation, assumed bridge, or incomplete Lean model a proof. A completion candidate must address the intended GRH scope, all analytic/arithmetic hypotheses, appropriate formal checks and independent adversarial review. Remaining informal and external dependencies must be explicit.

Routine unchanged/non-actionable runs stay quiet. Meaningful mathematical findings, important failures or blockers needing user action, and a rigorously supported completion candidate may surface in the chat. No new public publication, secret exposure, account linking, paid action, production dependency, infrastructure change or destructive operation is preauthorized by this loop.

## Operation

The heartbeat uses the existing local chat and repository; it is scheduled research rather than an uninterrupted process. The computer must remain on with the desktop app running and the project accessible for local scheduled work. Usage/account limits and app availability still apply. Manage or pause the task through the app's Scheduled view or ask in this chat.

Official scheduling documentation: https://learn.chatgpt.com/docs/automations . No persistent MCP configuration was changed to create the built-in app heartbeat.
