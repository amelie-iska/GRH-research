# Adaptive theta parameter design

DESIGN.md and the two top-level TeX proposals now match the implemented stricter raw interval test eta/4 and dynamic upward rounding of all five components. The literal reported sum is bounded by7eta/8. Each primitive series uses its own delta=2^(-p-16): weighted pi tail is bounded by20delta and the combined logarithm tail by(1+abs(k))delta before dyadic rounding. Precision p and rounding B are recorded; primitive series lengths are deterministically replayable, not individually serialized.

The prior design/README/checker and both proposals are preserved byte-identically in prior-v1/. The previous exact-parameters-v2.json, design-manifest-v1.json and three-page TeX compile remain untouched under outputs/checks/2026-11-05-adaptive-theta/design/. That prior checker used the initial raw budget convention and a process-only integer-string conversion setting; it is historical evidence.

The new check_serialized_design.py recomputes the same six truncation configurations and exact raw bounds, checks upward rounding of every component and the literal rounded sum using the worst allowed raw interval radius eta/4, and emits only compact exact dyadic bounds. It does not change Python integer-string limits, import producer arithmetic or evaluate special functions. Its final evidence is outputs/checks/2026-11-05-adaptive-theta/design/rounded-parameters-v4.json (six configurations,78 controls). The revised proposals compile together in two passes to proposal-check-v3.pdf (four pages, no warnings), with the wrapper, logs and stdout preserved in that directory. The revision/preservation receipt is design-manifest-v2.json.

All work stays on Linux and within the assigned design/check namespaces. Existing fixed theta/dyadic producers, final-v5 labels, final-v3 readouts and prior verification records are preserved.
